# Security boundary

The app has local password authentication and three roles. Operators can create incidents, run analysis, and ingest runbooks. Reviewers can approve or reject proposals. Admins can do both. All other incident and knowledge endpoints require a valid bearer session; the health and login endpoints are public. Approval identity comes from the authenticated account, not request content. Passwords use salted scrypt hashes, and opaque bearer sessions are stored as hashes, expire after 12 hours, and are revoked on logout. Create accounts with `python -m app.core.users_cli create-user --email you@example.com --role admin` after migrations.

This remains a local demo identity system. It lacks SSO, MFA, login rate limiting, account recovery, and a supported account disable/rotation workflow. Bearer tokens are held in browser session storage, so protect the frontend from script injection and use HTTPS for any shared deployment. Do not expose its write endpoints on the public internet yet. Agents produce analysis and proposals only. Approval records a decision; it does not run an action. Bedrock receives limited incident text and logs; never submit sensitive production logs without an approved data handling plan. Retrieved runbooks are displayed as cited data and cannot change graph instructions or allowed tools. The policy denylist is intentionally narrow and must be replaced before production use. CloudWatch uses read-only API calls under an operator-supplied IAM role. Secrets belong in environment or a managed secret store, never Git.
