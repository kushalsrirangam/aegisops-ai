# Architecture

FastAPI controllers validate and serialize requests, while `services/incidents.py` owns transactions and invokes the LangGraph graph. SQLAlchemy stores the incident lifecycle and run state. The graph itself has pure deterministic nodes in demo mode, apart from the optional Bedrock investigation adapter. Every agent step is copied into `agent_steps` for display. A native LangGraph interrupt pauses after security review. PostgreSQL checkpoints use a stable thread ID stored on the agent run, so a later request or restarted backend can resume the same graph with the human decision. Runs created before checkpointing retain a relational-state fallback.

Alembic revisions create the relational schema and add authentication and checkpoint thread columns. The backend then initializes LangGraph's own checkpoint tables. PostgreSQL uses a native `vector(64)` column; SQLite tests use JSON vectors and an in-memory checkpointer, so restart durability is verified in the PostgreSQL integration job. No Redis is required.
